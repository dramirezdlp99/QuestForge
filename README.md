## 🧭 ¿Qué es QuestForge?

**QuestForge** es una propuesta académica de plataforma web pensada para ayudar a las comunidades de videojuegos independientes a **organizar, descubrir y compartir mods y servidores personalizados**.

La idea es reunir información útil sobre las creaciones de la comunidad y facilitar que las personas encuentren contenido relacionado con sus juegos favoritos. El proyecto también sirve como caso práctico para aplicar herramientas y procesos de colaboración utilizados en el desarrollo de software.

> **Nuestra visión:** que encontrar y compartir nuevas formas de disfrutar un juego sea más sencillo para toda su comunidad.

## 🎯 Objetivos del proyecto

- 🗂️ **Organizar contenido:** plantear una forma clara de clasificar mods y servidores personalizados.
- 🎮 **Conectar comunidades:** facilitar el descubrimiento de contenido relacionado con videojuegos independientes.
- 🧩 **Presentar información útil:** contemplar datos como el juego, la versión y el estado del mod.
- 🤝 **Trabajar colaborativamente:** aplicar una dinámica de equipo con responsabilidades, seguimiento de tareas y revisión de cambios.
- 📚 **Documentar el proceso:** dejar evidencia de cómo se organizó y desarrolló el trabajo académico.

## 🔄 Flujo de colaboración

El trabajo se organiza mediante un flujo sencillo que permite mantener los cambios identificables y revisar las entregas:

```text
Tarea asignada
     ↓
Rama de trabajo
     ↓
Cambios y commits
     ↓
Pull Request
     ↓
Revisión de la entrega
     ↓
Merge
     ↓
Rama principal: main
```

### ¿Qué aporta cada paso?

1. **Tarea asignada:** define el objetivo y la responsabilidad de cada integrante.
2. **Rama de trabajo:** permite preparar cambios sin trabajar directamente sobre `main`.
3. **Commit:** registra un conjunto de cambios con un mensaje descriptivo.
4. **Pull Request:** presenta los cambios para su revisión y deja constancia de la propuesta.
5. **Revisión:** permite comprobar que la entrega corresponde con lo solicitado y detectar posibles ajustes.
6. **Merge:** integra los cambios aceptados en la rama de destino.

Este proceso permite mantener un historial consultable de las entregas y facilita la coordinación del equipo.
